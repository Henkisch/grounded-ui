# grounded-ui

Back to the basics: accessible, fast and compatible UI components that still look and feel great, with the receipts to prove it. The product is the **contracts and the conformance runner**; the reference CSS is the showcase that proves the contracts can be met with zero JavaScript and still look great. Mission and roadmap: Claude Docs `e22852ab-1520-4e2b-b06e-98b546f1e711` (read with the Claude Docs connector); it supersedes the older build plan.

## Source of truth

`contracts/<slug>/contract.yaml` is the single source. The conformance tests, the docs component pages and the scorecards are generated from it; warning CSS and editor validation will be too (not built yet). Edit the contract, then regenerate. Generated (gitignored): `docs/content/{components,examples,reports,recipes,_generated}/`, `docs/public/{demo,Grounded UI}/`, `dist/`, and `reports/<impl>/<slug>.{md,json}` are regenerated by `pnpm report <impl>`.

## Contracts

- Every rule has `level` (`normative`: a standard requires it; `recommended`: our judgement, open to review), `source` (a link) and `rationale`.
- Test selectors use part tokens (`{label}`, `{control}`, …), never Grounded UI's `data-part` hooks, so a binding can map parts to any implementation's markup. `:scope` is the component root; `{id}` is the root's id. `css.violation` (warnings) uses Grounded UI's hooks.
- Every rule needs `fixtures/broken/<RULE>.html` failing exactly that rule; declare unavoidable co-failures with `also: <RULE>` in its leading comment. `pnpm conformance` enforces this in three engines.
- Slug is identical in folder names, `component:` and `data-component`. Roots carry `data-component` only; parts carry `data-part`.
- Standards facts come from data packages, never from memory: `web-features` (contract `requires` takes feature ids), `@webref/elements`, `aria-query`, `html-validate`, the Baseline stylelint plugin.

## Reference CSS

- Everything in the repo is English. Size in `em` and `lh` (rem breaks on themes that set `html { font-size: 62.5% }`).
- Two files per component: `<slug>.css` (base: only what the contract and accessibility need, layer `grounded.components.<slug>`) and `<slug>.styled.css` (the look, layer `grounded.styled.<slug>`). A rule goes in base only if removing it would break the contract or accessibility.
- Every file repeats `@layer grounded.core, grounded.components, grounded.styled, grounded.warnings;`; the validator enforces it.
- Donut scope: `@scope ([data-component="<slug>"]) to ([data-component])`, so a component never styles a nested one.
- Defaults live only in the `var(--grounded-*, fallback)` fallbacks. Never set tokens on `[data-component]` in Grounded UI CSS: it would block themes set on an ancestor.
- `pnpm check` must pass before committing.

## Docs (Blume 2)

Run Blume's CLI as `pnpm --filter docs exec blume <command>`. Before changing `docs/`, read `docs/node_modules/blume/skills/blume/SKILL.md` (full docs in `docs/node_modules/blume/docs/`, online at https://useblume.dev/docs).

- Use Blume's built-in components only. Custom docs code is limited to `docs/scripts/generate.mjs` + `docs/scripts/lib/` and `docs/public/demo-frame.js` (fits demo iframes, mirrors Blume's theme into them).
- Demos are raw-HTML iframes with only Grounded UI CSS, never Astro components.
- `dev`/`build` run the budget and generator once at start (the scorecard needs Chromium); restart `dev` after editing a contract. Routes have no trailing slash.
- `examples/*.html` are composed page fragments; their `title:` and `description:` comments become the page. Page layout CSS belongs in the example.
- `recipes/<slug>.md` (+ optional `<slug>.html` demo with its own CSS) are CSS recipes for styling native elements. Frontmatter `features:` lists web-features ids; the generator renders browser support from the data, never typed by hand.
