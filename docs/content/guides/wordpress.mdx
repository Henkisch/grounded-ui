## Test your WordPress forms first

Before changing anything, run the contracts against a page of your existing site. It shows what already works and what doesn't, whether or not you use Grounded UI's CSS:

```sh
npx grounded-conformance https://your-site.example/contact --binding your-theme.text-field.binding.yaml
```

See [Test your components](/getting-started/test-your-components) for writing the binding.

## Load the stylesheets

Copy `core/` and the component folders into your theme, then enqueue them on `enqueue_block_assets`. That hook runs on the front end **and** inside the block editor's iframe, so blocks preview correctly while editing.

```php
// functions.php
add_action( 'enqueue_block_assets', function () {
    $base = get_theme_file_uri( 'grounded-ui' );
    wp_enqueue_style( 'grounded-core', "$base/reference/core/core.css", [], '0.1.0' );

    foreach ( [ 'text-field', 'dialog' ] as $component ) {
        wp_enqueue_style(
            "grounded-$component",
            "$base/reference/$component/$component.css",
            [ 'grounded-core' ],
            '0.1.0'
        );
    }
} );
```

Classic editor (TinyMCE) themes load editor CSS with `add_editor_style()` instead.

## Use a component

Paste the markup into a **Custom HTML** block. The block keeps `data-*` attributes as written.

## Map your theme's tokens

Point Grounded UI's custom properties at your `theme.json` presets, so a colour change in the Site Editor reaches the components:

```css
:root {
  --gui-focus: var(--wp--preset--color--primary);
  --gui-radius: var(--wp--custom--radius, 0.25em);
}
```

## Heavy themes and page builders

Elementor, Divi and older Bootstrap themes ship aggressive resets. They're usually unlayered, so they win over grounded. If a component looks off, look for a theme rule on bare elements (`input`, `button`, `p`) and scope it away from `[data-gui]` in your child theme.
