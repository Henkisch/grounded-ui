## Test your Drupal forms first

Before changing anything, run the contracts against a page of your existing site. It shows what already works and what doesn't, whether or not you use grund's CSS:

```sh
npx grund-conformance https://your-site.example/contact --binding your-theme.text-field.binding.yaml
```

See [Test your components](/getting-started/test-your-components) for writing the binding.

## Define a library

```yaml
# mytheme.libraries.yml
grund:
  version: 0.1.0
  css:
    component:
      grund-ui/reference/core/core.css: {}
      grund-ui/reference/text-field/text-field.css: {}
      grund-ui/reference/dialog/dialog.css: {}
```

Attach it globally:

```yaml
# mytheme.info.yml
libraries:
  - mytheme/grund
```

## CKEditor 5

Load the same CSS in the editor so content previews correctly:

```yaml
# mytheme.info.yml
ckeditor5-stylesheets:
  - grund-ui/reference/core/core.css
  - grund-ui/reference/text-field/text-field.css
```

Restricted text formats strip unknown attributes. Allow the hooks the components use in the format's **Allowed HTML tags**, for example:

```html
<div data-component data-part data-variant> <label for data-part> <p id data-part>
<dialog id data-component data-variant aria-labelledby aria-describedby closedby role>
<button type commandfor command>
```

## CSS aggregation

Aggregation combines and may reorder the files. That's safe: every grund file declares the full layer order at the top, so the first file to load sets the same order. See [cascade layers](/styling/cascade-layers).

## Single Directory Components

A grund component maps directly onto an SDC: copy the markup into `component.twig`, put the stylesheet next to it, and read attributes from props. Generated SDC output is on the roadmap.
